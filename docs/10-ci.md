# 离线 CI 与本地统一检查

R13 增加 .github/workflows/ci.yml 与 scripts/check.py。工作流在 main 推送、PR 和手动触发时执行，不部署、不发布，也不请求真实模型。

## 本地运行

先按 README 安装 requirements.lock 与 package-lock.json 对应的依赖，再执行：

```bash
# 顺序执行后端、构建、离线评测、桌面/手机浏览器
.venv312/bin/python scripts/check.py

# 只执行某个阶段；browser 阶段要求已完成网页构建
.venv312/bin/python scripts/check.py --stage backend
.venv312/bin/python scripts/check.py --stage web
.venv312/bin/python scripts/check.py --stage eval
.venv312/bin/python scripts/check.py --stage browser
```

入口使用当前 Python 解释器，工作目录固定到项目根，不自动安装依赖、不读取 .env。清除继承的模型供应商/FamilyAgent 配置与 PYTEST_ADDOPTS，强制 demo，并设置临时数据库；避免本地真实模型配置、用户数据路径或筛选测试参数进入检查。浏览器服务单独使用自己的临时库并显式开启嵌入 Worker。

任一命令非零即停止后续检查，原退出码传给 CI；找不到命令或中断也记录失败。每次产生独立的 test-results/ci/{随机ID}/summary.json，报告阶段、实际执行命令及退出码；后端另有 backend.xml，eval 阶段保存工程检查与记忆检索报告，不覆盖历史结果。全部产物处于 gitignore 范围。

## 浏览器可移植性

- PYTHON_BIN 可指定解释器；否则优先本地 .venv312/bin/python，再使用 PATH 上的 python3。统一检查入口会明确传入自身解释器。
- CHROME_PATH 可显式指定 Chrome；非 CI 的 macOS 保留已安装 Chrome 的兼容选择，其他情况使用 Playwright 自带浏览器。Linux CI 不依赖本机 macOS 路径。
- 8010 端口被占用时直接失败；检查子进程退出、demo 健康状态与就绪超时，不静默复用已有服务。结束时等待测试 API 退出，必要时强制结束自己创建的子进程，不停止其他端口。

首次使用自带浏览器可运行 `npx playwright install chromium`；Linux 通常需 `npx playwright install --with-deps chromium`。不要同时在同一目录构建网页和执行浏览器测试，也不要同时运行两份占用 8010 的测试。

## 验证范围与尚未完成

本轮通过统一入口在本机验证各阶段，包括实际桌面/手机浏览器；工作流另做本地 YAML 语法检查。没有推送或触发 GitHub，不能宣称 Ubuntu runner、云端依赖安装、缓存或产物上传已经实际通过。Linux Chromium 路径须在首次远端运行继续验收；当前本机浏览器证据来自 macOS Chrome。

这些检查验证合成案例的工程行为，不等于真实模型质量、安全审计、生产负载或人工验收。工作流配置不自动开启分支保护；只有用户发布后并在仓库设置必需检查，才会阻止未通过检查的 PR 合并。当前未启用部署、收费模型评测、完整操作系统/语言版本矩阵或覆盖率门槛。
