# 消息分页与工作台摘要

R10 优化网页的数据读取。原有完整接口仍兼容；默认 API 行为没有强制改为分页。

## 接口

| 接口 | 行为 |
| --- | --- |
| GET /api/state?compact=true | 返回工作台信息与运行摘要；摘要在 SQL 投影，不装载 results、prompt、steps、工具结果等完整运行正文 |
| GET /api/conversations/{id}?compact=true | 首次返回最新 50 条消息（按插入顺序正序）、分页信息、最新一条完整运行及会话信息 |
| GET /api/conversations/{id}?compact=true&after={message_id} | 返回游标之后最早的最多 50 条消息；同时刷新最新运行状态 |
| GET /api/conversations/{id}/messages?limit=50&before={message_id} | 返回游标之前最近一页；limit 为 1–100，默认 50 |
| GET /api/conversations/{id}/messages?after={message_id} | 从游标往后读一页；before/after 互斥 |
| GET /api/conversations/{id}/messages/{message_id}/sources | 只解析该消息的当前记忆来源状态，重新检查权限、存在性与内容指纹 |
| GET /api/runs/{id} | 原有完整运行接口，网页进入运行观察后按选中项读取 |

消息响应包含 messages 和 page。page.direction 为 before 或 after，has_more 指示查询方向上是否还有记录，oldest/newest 是本页第一/最后一条消息 ID。空页的两个游标为 null；客户端保留原来的进度。查询多取一条判断 has_more，没有全量 COUNT。

游标使用消息 ID，在当前会话内定位 seq，再进行严格大于/小于的范围查询。不能把另一段会话的消息当游标；未知/失效游标返回 422；会话无权限仍按既有策略返回 404。参数化 SQL，不以时间戳或 OFFSET 分页。API 必须先授权会话，再定位游标和解析来源。

## 网页状态

- 首次打开空间加载最新 50 条，出现“加载更早的消息”时可向前翻页。
- 轮询只追加上次 newest 之后的消息，按 ID 去重；已加载的旧页保留。超过一页的积压由后续轮询继续追赶，不直接跳到尾部。
- 同一会话增量请求不重叠；切换会话或卸载后丢弃旧响应。旧页插入后恢复滚动位置，不自动跳到底部。
- 最新一条运行仍完整返回，以保留审批、工具等待、暂停/恢复等功能。历史运行在运行观察中选中后再获取；工作台轮询仅传输摘要。
- 已展开的记忆来源面板独立每 2.5 秒复核；折叠后停止。请求失败时隐藏来源正文并显示核验失败，不用无限期缓存来源权限。已生成回复正文仍不自动清除。

浏览器回归发现增量消息会让已展开来源停留在删除前状态，因此增加上述来源接口及独立刷新，而不是恢复全量消息轮询。

## 范围与限制

这是载荷与读取方式优化，不是生产吞吐基准。工作台仍全量返回可访问的会话、运行摘要和个人任务等列表；除运行摘要 SQL 投影外，其他列表仍保留原有读取方式。最新单次运行可能很大，没有为完整运行正文设字节上限。主动加载的消息会保存在当前页面内存，尚无虚拟列表或自动淘汰；离开空间后释放。轮询仍存在，没有改为 SSE。

删除游标消息时需要重新打开会话。当前消息没有编辑/删除业务接口，增量协议也不提供通用编辑/删除同步流。记忆来源独立复核不等于全量历史消息持续刷新。向前分页时的新写入不会改变已定位的旧页边界，但这不是跨多次请求的全库快照。R10 本身没有新增迁移；R11 已升级为 v3，分页内部改用 messages 表的显式 seq，消息 ID 游标和对外响应保持兼容。
