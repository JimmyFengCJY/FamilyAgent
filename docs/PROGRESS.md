## R1：按意图区分交互，拆开会议结论与任务（2026-10-24）

### 问题

统一提示词鼓励所有回复附加 suggested_actions；后端看到非空数组就弹出任务确认。会议成员确认同时创建发起人的任务，混淆了“同意结论”和“接受待办”。

### 本轮实现

- 按消息记录 question / support / advice / planning / task / discussion，保存规则或用户选择来源，并写入运行事件；不额外消耗模型调用。
- 会议中的解释问答或倾听请求只调用主持人一次，不启动整套专家讨论。
- 网页输入框增加本条消息处理方式，发送后恢复自动判断；角色/空间本身不授予任务意图。自动规则不明确时先给建议。
- 模型提示词明确允许无行动项；后端再过滤问答、倾听、明确不创建任务的输出，不能只依赖提示词。
- 建议仅作为候选，用户可选择“整理为任务草案”，先预览，再确认写入；明确规划/任务需求才自动呈现任务草案。
- 家庭会议先逐成员确认讨论结论，确认不创建任何任务；之后发起人可单独将潜在行动转成自己的待办，并再次确认。
- 审批绑定类型、正文、行动、审批人、有效期、版本及接收人；保留独立的会议确认记录。新讨论后不能转换旧建议；重复确认不会重复创建任务。
- 旧版本待确认草案拒绝按新规则执行，需发送新消息重新生成，避免旧版“同意即建任务”被无提示保留。已有任务不受影响。
- 健康检查和启动器增加代码/网页构建指纹核对，防止更新代码后静默复用旧进程。
- 建立本进度文件及项目 AGENTS.md，以后每轮继续追加记录。

### 验证

- 完整后端测试：95 项通过。包含模型强行返回行动时的后端过滤、规划空间普通问答、用户选择覆盖、建议主动转换、会议确认不建任务、任务独立授权、旧草案拒绝、重复操作去重等。
- 网页验证：TypeScript 检查与 Vite 生产构建通过。
- Chrome 桌面/手机浏览器回归通过：问答无任务按钮、建议可选转换后再确认、会议两阶段确认、个人规划、隐私、预算、角色、调用预算恢复与运行观察。使用隔离演示数据库；截图在被忽略的 test-results/。
- 20 案例离线回归：26 次运行、50 次演示调用全部完成，工程检查通过。报告位于 evals/results/r1-intent-regression/report.md；0 条人工质量评分，不能由此声称模型质量提升。
- 已在本机重启服务。health 确认 interaction_policy=intent-v1、模型仍为用户已配置的 gemini-3.1-flash-lite，runtime_revision 与当前后端及网页构建一致。
- 本轮未进行新的付费模型调用，真实模型下的新行为及用户交互体验尚待验收。已知测试依赖的 httpx2 弃用提示仍存在，不影响当前测试通过。
- R1 收尾时变更保留在本地，未自动上传；后续用户授权发布见下方记录。

### 限制与下一步

- 当前是保守的中文规则路由，不能完整理解复杂语义；用户可手动纠正。尚未增加额外 LLM 意图分类器或声称识别准确率。
- 转任务目前采用整组候选预览，尚无逐项勾选、编辑或分配给其他成员。
- 真实模型下的新交互尚需用户验收；本轮不自动跑付费批量评测。
- 下一里程碑 R2：使用已可用 Gemini 做少量受控真实对照并人工评分，再运行完整基线；有证据后开展首轮独立分析/分歧澄清。
