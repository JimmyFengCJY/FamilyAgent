# FamilyAgent 需求分析

版本：v0.1 设计草案 · 2026-10-13

## 1. 产品定位与假设

FamilyAgent 是面向个人与家庭的多 Agent 协作空间。用户可以选择不同人格的 AI 伙伴，邀请具有不同能力的 AI 参与讨论，将讨论转化为计划，并持续跟进执行。

核心闭环：**表达问题 → 澄清目标 → 选择参与者 → 协作讨论 → 用户决定 → 形成行动 → 跟进复盘**。

本轮假设：中文优先、先做文本 Web 应用、支持一个家庭中的多个独立账号；以个人长期使用和小规模家庭协作为首要目标。初版不接银行交易、不自动对外发送消息。技术栈、预算和具体供应商尚未由用户确认。

用户提出的全部场景属于产品目标；下文 MVP 是建议的开发顺序，不表示删除心理支持、理财或个人助手需求。

## 2. 用户与空间

| 对象 | 需求 | 权限原则 |
| --- | --- | --- |
| 个人用户 | 私密聊天、个人规划、任务提醒、角色陪伴 | 默认只有本人可访问 |
| 家庭成员 | 共同会议、共享计划、分工、共同预算 | 仅访问明确共享的信息 |
| 家庭管理员 | 邀请成员、管理成员资格、家庭公共配置 | 管理身份不授予读取其他成员私密聊天的权限 |
| AI 角色 | 按指定风格和专业能力参与 | 只能访问此次运行明确授权的数据和工具 |

空间分为个人空间与家庭空间。会议还有独立参与名单；加入家庭不等于自动加入所有会议。邀请、离开、移除成员都应改变后续访问权限。

真实成员和 AI 角色必须有清晰不同的标识。AI 可以模拟“站在父母角度考虑”，不能将模拟意见记录成真实父母的同意。

## 3. 角色扮演需求

角色由四部分组成：人格设定、专业能力、知识/记忆范围、工具权限。

人格示例：温和倾听者、理性分析师、严格教练、幽默伙伴。专业能力示例：会议主持、计划拆解、情绪支持、财务分析、日常事务。

同一种能力可以采用不同人格；同一个人格也可以绑定多种能力。人格调整表达方式，不改变系统规则、事实要求或工具权限。多个角色可以共享同一个底层模型，不需要每个角色单独训练模型。

必要功能：创建、编辑、复制、归档角色；设定称呼、语气、背景、发言偏好；预览一段对话；选择可用能力；查看角色可访问的数据。角色设定必须版本化，历史会话能追溯当时配置。

第一期提供预设角色和有限自定义。开放第三方角色市场与任意代码技能放在后期。

## 4. 核心场景

### 4.1 家庭会议：主场景

例：“下个月是否去旅行，预算多少，谁负责安排？”

1. 发起人填写议题、目标、参与成员、AI 角色和讨论预算。
2. 主持人检查必要信息，提出议程和待确认问题。
3. 真实成员发言；AI 角色基于授权资料分别提供方案。
4. 主持人收敛为共识、分歧、备选方案与待决定事项。
5. 成员明确确认决议；可保留不同意见，不能强行生成一致结论。
6. 将已确认事项转换为任务、负责人和截止日期。
7. 后续会议复盘执行情况。

支持异步参与、暂停、恢复、用户随时插话、指定角色回答、跳过角色。必须区分“AI 建议”“成员表态”“已确认决议”。涉及个人隐私的发言，发布到会议前应提供预览。

输出：会议纪要、决策记录、未决问题、行动清单。为其他成员分配任务先形成待接受邀请，不能由 AI 代替该成员承诺。

### 4.2 个人规划

例：“三个月提升英语，工作日每天最多半小时。”

流程：澄清目标与约束 → 评估当前状态 → 拆分里程碑 → 安排任务 → 用户接受 → 定期复盘 → 调整。

规划师负责结构，教练负责执行建议；必要时才引入其他角色。计划调整保留版本与原因，延期不直接判断为个人失败。任务应有可执行动作和完成标准。

输出：目标卡、阶段计划、周计划、复盘记录。计划、提醒、实际完成状态分别记录。

### 4.3 心理支持与闲聊

用户说的“心理咨询”在首版定位为情绪支持、自我梳理、沟通练习和陪伴闲聊。支持倾听模式、问题解决模式与角色扮演练习，先让用户决定当前需要哪种互动。

不提供医疗诊断、处方或冒充持证治疗师。出现明显危机信号时切换到预先设计并经评审的支持流程，暂停娱乐性角色设定；不自动通知家人、不将私密内容共享到家庭会议。实际危机资源需要按地区核实。

默认不跨会话保存心理敏感摘要，用户可主动选择保存。提供“本次不记忆”和删除入口；删除需覆盖摘要、索引、缓存等派生副本，备份按明确保留策略到期清除。

### 4.4 理财分析

首版优先支持收支分类、预算、储蓄目标、家庭现金流与情景测算。数据由用户手工录入或上传文件，系统先预览识别结果，待用户确认后入账。

金额计算交给确定性计算工具，模型负责解释。每份报告明确数据时间、来源、币种、缺失项与假设。示例预测必须标记为情景，不表达为保证收益。

查询市场数据属于后续连接能力，必须标明数据时间和来源；没有实时数据时不能声称实时。初版不连接交易、不执行买卖、不代管账户密码。个人账本和家庭账本分开授权。

### 4.5 日常个人助手

支持待办、清单、提醒、信息整理、日程草案和知识问答。外部日历、邮件等连接器逐项授权，先读取再扩展写入。

创建本地待办可按用户指令直接执行；向他人发消息、写入外部共享日历、删除外部数据等动作，需要展示具体内容与影响后确认。提醒只有被调度器持久化后才显示“已设置”。

## 5. 交互与信息架构

建议主导航：今天、聊天、家庭会议、计划与任务、角色、资料与记忆、设置。

聊天页展示参与者、当前发言者、工作状态和可展开的结果依据；会议页额外展示议程、共识/分歧和决议草稿。角色详情展示人格与能力，隐私入口展示谁可以读取什么。

用任务状态解释系统正在做什么，不展示模型隐藏思维链。调试视图可展示计划摘要、工具调用、证据、预算和错误事件。

必要用户控制：停止、继续、重试、编辑消息后建立新分支、撤销未执行动作、查看与管理记忆。已发生的外部动作需要补偿操作，不能用删除聊天冒充撤销。

## 6. MVP 与迭代范围

| 阶段 | 交付范围 | 主要验证 |
| --- | --- | --- |
| M0：运行骨架 | 文本单聊、预设角色、工具调用、运行事件、取消与恢复、权限隔离 | Harness 是否可靠 |
| M1：家庭会议闭环 | 独立成员账号、会议权限、主持人和专家轮次、纪要确认、任务接受 | 多角色是否改善家庭决策 |
| M2：个人持续使用 | 规划与复盘、本地提醒、可管理记忆、私密情绪支持 | 跨会话是否连续且可控 |
| M3：财务与外部工具 | 文件账本、预算测算、数据出处、日历/检索连接器 | 工具与数据是否可信 |
| 后续扩展 | 语音、数字形象、第三方角色、复杂定期工作流 | 是否存在明确使用价值 |

建议第一个演示串联家庭会议、个人计划、任务跟进，另用独立会话演示私密情绪支持和预算分析，避免将所有敏感信息塞进一次会议。

## 7. 非功能需求与验收

以下数值是初始工程目标，需要在选定模型和部署环境后测量修订。

| 维度 | 需求/初始目标 | 验证方式 |
| --- | --- | --- |
| 权限 | 跨账号、跨家庭和私密空间访问均拒绝 | API、检索、任务恢复及流式订阅越权用例 |
| 决议真实性 | AI 不能伪造成员同意 | 多人会议含分歧、缺席、撤回场景 |
| 可恢复 | 服务重启后可恢复未结束任务；不重复外部写入 | 在工具调用前后注入中断 |
| 可控 | 默认每次运行最多 3 个专家、2 轮讨论、12 次模型调用 | 预算耗尽与无限讨论场景 |
| 响应 | p95 在 2 秒内返回已接收/工作状态；生成耗时另记 | 约定并发下实测 |
| 停止 | 收到停止后不派发新步骤；在途动作报告真实状态 | 取消前后工具执行测试 |
| 计算 | 财务数值与确定性计算器结果一致 | 币种、舍入、日期和缺失值案例 |
| 隐私 | 敏感信息默认不入共享记忆；删除覆盖派生数据 | 数据流与删除链路测试 |
| 可观察 | 每次运行可查版本、工具、耗时、成本及失败节点 | 查看完整运行轨迹 |
| 质量 | 先建立固定案例集，与单 Agent 基线比较 | 任务完成、事实正确、行动清晰度、成本评测 |

## 8. 待确认产品决策

不阻塞当前设计，但实施前需决定：优先个人使用还是家庭多人上线；是否包含未成年人；情绪支持和财务数据的部署与保留要求；可接受的单次会议成本；是否需要首版语音；首批外部连接器。

默认按成年人使用、多人数据隔离、文本优先、工具按需接入设计。未成年人功能需要独立需求评审，不能直接沿用成人私密空间设计。
